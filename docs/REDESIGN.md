# AbangQue passenger redesign

Implemented on 2026-10-31. Pre-change checkpoint: `40e22a2`, tagged
`pre-abangque-glass`. The working Flutter foundation passed analysis and 18 tests
before the redesign.

## Design and behavior

The four passenger destinations share emerald/mint accents, a cream background,
reflection borders, translucent panels, rounded controls and modern Material 3
typography. GlassPanel, GlassBackdrop, GlassIconButton, SoftEntrance and
PassengerButton centralize surfaces, motion and wrapping action text.

The home hero has no fixed-height text layer or overlapping artwork. Cards stack
on narrow screens; labels and buttons wrap at enlarged text sizes. Navigation
respects system safe areas. The details sheet scrolls independently. A selected
map marker reveals a report panel, with a details action and dismiss control.

Only navigation uses clipped sigma-8 backdrop blur. Cards/map controls use static
translucency, gradients and shadows. Custom entrance motion lasts 220ms and runs
on page changes, not a loop. Reduced-motion settings disable the custom entrance
and backdrop blur. No packages were added.

The user-facing brand is AbangQue. Internal `jeeplink` identifiers remain for
compatibility. Numerical passenger/seat fields are removed from the model and
simulator, not merely hidden. FULL/AVAILABLE is explicit manually reported status.
Both modes show ETA unavailable, even if a future API payload supplies an ETA.
Fresh-report statistics count only non-stale online device records with report
and communication timestamps. Historical DEMO rows never count as fresh or
available. Missing/stale status remains UNKNOWN/STALE.

The GET repository, shared search/filter controller, polling, loading, refresh,
retry and empty states remain intact. No credentials are stored in Flutter.
OpenStreetMap tiles, markers, zoom/reset, attribution and tile-error retry remain.
The unverified sample pickup marker is removed. Backend/schema and release HTTP
restrictions are unchanged. No admin, firmware or deployment work is included.

## Automated and rendered checks

Final results for this change: `flutter analyze` passed with no issues;
`flutter test` passed all 21 tests; the Android debug APK built successfully.
Artifact: build/app/outputs/flutter-apk/app-debug.apk, API mode targeting
http://127.0.0.1:3000 for the USB-reversed phone workflow. No phone installation,
fresh PostgreSQL/API runtime check or performance measurement was performed.

The first Android build attempts failed in Java's local socket setup with
`Unable to establish loopback connection`. A process-local socket directory
resolved it. If this host reproduces that error, run in a dedicated PowerShell
terminal from the project root:

```powershell
New-Item -ItemType Directory -Force -Path build/jvm-tmp | Out-Null
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:/Users/Administrator/Projects/jeeplink/build/jvm-tmp'
flutter build apk --debug --dart-define=DATA_MODE=api --dart-define=API_BASE_URL=http://127.0.0.1:3000
```

Adjust the path if the project moves, and close that terminal afterward. This
changes only the build process environment, not system settings or Android
network permissions. The socket-directory property is documented in
[Oracle's Java networking reference](https://docs.oracle.com/en/java/javase/24/core/java-networking.html).

Run from the project root:

```powershell
flutter analyze
flutter test
flutter build apk --debug --dart-define=DATA_MODE=api --dart-define=API_BASE_URL=http://127.0.0.1:3000
```

Tests cover API configuration/security, historical status, fresh report counting,
unavailable ETA, GET-only requests, malformed responses/timeouts, refresh/retry,
demo/controller behavior, navigation, search/filter, map selection/controls,
details, guide, empty/loading/error states, 320-pixel layouts at 1x/1.8x/2x text,
keyboard and gesture insets, and reduced motion. Test map tiles and HTTP are
mocked. They do not establish PostgreSQL health, GPS operation or phone speed.

Optional previews are generated by:

```powershell
flutter test test/glass_accessibility_test.dart --dart-define=CAPTURE_DESIGN=true --dart-define=DESIGN_FONT_DIR=C:/Users/Administrator/Documents/flutter/bin/cache/artifacts/material_fonts
```

Change DESIGN_FONT_DIR to your Flutter SDK's bin/cache/artifacts/material_fonts
directory. Without it, Flutter tests use the block-shaped Ahem test font. Images
are saved to build/design-preview. The map images use mock tiles, not a real
geographic rendering. Rendered previews were reviewed for spacing and contrast.

## Remaining physical-phone acceptance

Use [API_MODE.md](API_MODE.md) for the Infinix X6885 / Android 16 USB workflow.

1. Verify the installed name is AbangQue and Home text remains visible at the
   phone's default and largest practical font/display settings.
2. With PostgreSQL/backend running, compare IDs/status/timestamps to the endpoint.
   Two historical DEMO fixtures should show stale/unknown, zero available/fresh
   reports and ETA unavailable. Do not reseed just to make reports look fresh.
3. Check every tab, scrolling, keyboard/search, filters, details, map selection,
   focus/reset/zoom and Android gesture/navigation insets.
4. Check OSM tiles/attribution on the phone's connection. Disable connectivity to
   exercise tile retry and API timeout/retry; restore it and refresh. API failures
   must not silently start the simulator.
5. Relaunch explicitly in DEMO mode; confirm fictional labels, manual-status
   examples and unavailable ETA throughout.
6. Assess scroll/map smoothness and heat on the phone, including reduced-motion
   settings. Debug builds are not a reliable production performance benchmark;
   a future profile API run needs an actual HTTPS backend. No FPS claim is made.

Real GPS/LTE ingestion, verified routes/terminals, ETA calculation and field
accuracy remain future work. This redesign does not establish live tracking.
